# 合成试点：从计划到效果

这里的四份原稿、项目、日期、数量和效果说法均为虚构，专门测试追溯流程，不对应 WISER、客户、员工或任何真实项目。

## 完整链条

1. `sources/`：规划、旧简报、登记摘记、修订版，共四份材料。
2. `evidence.json`：来源清单、SHA-256、版本关系及五项论断。
3. `traceable-brief.md`：由脚本生成的逐项追溯底稿。
4. `article.md`：面向读者的专题样稿，保留论断 ID 与出处。
5. `review.md`：实际审阅及测试记录，不把 AI 复核写成人工认可。

这个例子故意保留“目标 20%”“旧简报 30%”及十项与八项之间的范围和明细缺口。正确产物不能把它们合成为一个成功故事，也不能把缺少签记写成失败。

重建底稿：

```bash
python3 scripts/render_brief.py examples/synthetic-pilot/evidence.json --public > /tmp/traceable-brief.md
```

从仓库根目录执行。生成结果可与本目录底稿比较。其他真实材料应在单独、访问范围合适的目录处理，不能为了运行此例而提交到公开仓库。
