# 审阅与公开检查

## 证据审阅

对每项重要论断重新打开引文上下文，确认主体、时间、数量、计量口径和否定词一致。来源中的“预计”“试行”“待确认”“自述”不可被摘要删除。分母、样本、对照、测量窗口和缺失值不足时，不推断效果或因果。

版本优先级不能只看日期。区分作者修订、独立观察、会议意见和宣传材料，检查谁有权确认哪一项事实。相互矛盾时写出双方依据及不能判断的部分，不用多数投票代替核验。

抽查不能代表逐项验证。分别记录机器检查、作者复核、独立审阅及未执行的步骤。AI 审阅不得写作人工审阅、同行评审或用户认可。

## 公开包

审查实际要发布的全部文件，包括 Git 历史、截图、附件、文件名、路径、评论、日志、测试数据和元数据。只发布通用方法、可以合法使用的公开材料和明确标注的合成例子。用于研究的私有材料不因成果公开而自动获准公开。

授权应覆盖具体材料、接收方／公开渠道和用途。移除姓名不一定构成充分匿名化。公开链接不证明版权许可；必要的短引文保留归属，长文或整篇转载需相应权利。不要把第三方材料的许可改写为对整个仓库的许可。

脚本不自动脱敏、不删除原始资料、不对外传输，也不产生发布授权。没有明确许可时继续交付私有草稿或公开方法说明，把待授权材料留在公开包之外。

## 小样验收

最小可用闭环应能回答：

1. 重要论断能否回到确实读取的原文位置？
2. 读者能否分清历史计划、记录事实、推论和假设？
3. 矛盾和缺失是否保留，并影响结论强度？
4. 样稿离开内部资料还能读懂，必要出处仍可追溯吗？
5. 源文件是否保持不变，公开材料是否逐项符合权限和版权边界？
6. 复核者、范围、修订和未完成事项是否如实说明？

本仓库的合成小样只能验证流程是否可用。真实材料的覆盖、版权确认、领域专家审阅、读者反馈与业务成效仍是独立工作，不随演练通过自动完成。
